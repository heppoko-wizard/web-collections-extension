# パネルのリファクタリングおよびローカルフォルダ同期刷新仕様書 (v2)

## 1. 目的
`panel.js` の分割を維持しつつ、同期メカニズムを「単一JSON」から「Manifest + 個別Collection JSON」の分散管理方式へ刷新する。
また、同期負荷を最小化するため、Base64形式での画像保存機能を廃止し、メタデータ中心の高速なバックグラウンド同期を実現する。

## 2. アーキテクチャの変更点

### 2.1 同期データの分散管理（共有フォルダ内）
単一の `collections.json` への依存を排除し、以下の構造で共有フォルダを管理する。

*   `manifest.json`: コレクションの一覧（メタデータのみ）。差分検知のインデックスとして機能。
*   `collections/[UUID].json`: 各コレクションの実体データ（アイテムの配列を含む）。

これにより、特定のコレクションが更新された際、そのファイルのみを書き換えるだけで同期が完了する（アトミックな更新）。

### 2.2 画像処理機能の完全廃止
*   **現状**: `image-processor.js`, `image-optimizer.js` を使用して画像をBase64化し、IndexedDBおよびクラウドへ保存。
*   **刷新後**: 画像は `imageUrl`（元のURL）のみを保持する。画像保存サイズ設定（リサイズ機能）もUIから削除する。

### 2.3 バックグラウンド完全主導の同期 (Always-on Sync)
*   `background.js` がデータ変更（右クリック追加、削除、並べ替え等）を検知した直後、即座に変更があった `collections/[UUID].json` と `manifest.json` を共有フォルダへ書き出す。
*   File System Access API の権限がある限り、サイドパネルが閉じていても同期を継続する。

## 3. 実装の役割分担

### 3.1 同期・データ層
*   `sync-manager.js`: 分散管理方式に対応した同期フローのオーケストレーション。
*   `folder-sync.js`: `collections/` ディレクトリ内の個別ファイル操作のサポート。
*   `storage.js`: 画像処理フックの削除、論理削除と `updatedAt` 管理の徹底。

### 3.2 UI・イベント層
*   `html/sidepanel.html`: 画像保存設定項目の削除。
*   `panel-actions.js`: 画像設定関連のロジック削除、分散同期への対応。

## 4. 移行プロセス
1.  **画像データのクリーンアップ**: 既存のBase64データはマイグレーション時に維持するか、あるいは軽量化のために破棄する（要検討）。
2.  **分散ファイルへの書き出し**: 初回同期時に、現在のIndexedDBデータを `manifest.json` と `collections/*.json` へ一斉変換して書き出す。

## 5. 制約事項
1.  **ユーザージェスチャー**: ブラウザ再起動後の初回権限取得には、引き続きサイドパネルでの「再許可」クリックが必要。
2.  **ファイルシステム性能**: OS側のファイルシステム制約を考慮し、コレクション数は現実的な範囲（数百程度）を想定する。
