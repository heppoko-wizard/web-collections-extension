# マルチライター方式による高信頼同期仕様書

## 1. 目的
複数デバイスから同時に書き込みが発生した場合でも、データの上書き消失を防ぎ、各デバイスの変更をアイテム単位で確実に統合（マージ）する同期システムを構築する。

## 2. コア概念

### 2.1 デバイスID (Device ID)
*   各ブラウザ（プロファイル）ごとに一意のID（UUID v4）を初回起動時に生成し、IndexedDBに永続化する。
*   このIDはファイル名の一部として使用され、書き込み時の競合を物理的に回避する。

### 2.2 ファイル構造（共有フォルダ内）
*   `manifests/manifest_[DeviceID].json`: デバイスごとの目次。
*   `collections/collection_[CollectionUUID]_[DeviceID].json`: デバイスごとのコレクション実体。

## 3. 同期アルゴリズム

### 3.1 書き出し (Push)
*   自分の `DeviceID` が付与されたファイルのみを作成・更新する。
*   コレクションの更新時は、まず `collection_[UUID]_[DeviceID].json` を書き出し、成功後に `manifest_[DeviceID].json` を更新する。

### 3.2 統合マージ (Pull & Merge)
読み込み時、以下のステップで全デバイスのデータをマージする。

1.  **全マニフェストのスキャン**: `manifests/` フォルダ内の全ファイルを読み込む。
2.  **更新が必要なファイルの特定**: ローカルの `updatedAt` よりも新しい `updatedAt` を持つ全てのデバイスの全コレクションファイルをリストアップする。
3.  **アイテムレベルの LWW マージ**:
    *   全デバイスの該当コレクションファイルをパースし、アイテムUUIDをキーとした Map に展開する。
    *   同一UUIDのアイテムが複数存在する場合、`updatedAt` が最も新しいプロパティを採用する。
    *   `isDeleted: true` のアイテムも同様に `updatedAt` で判定し、削除状態を伝搬させる。
4.  **IndexedDB の更新**: マージ結果をローカルDBに保存する。

## 4. データ整合性とクリーンアップ

### 4.1 書き込みの整合性
*   常にコレクションファイルを先に書き込み、マニフェストを後に更新することで、不完全なデータがマージされるのを防ぐ。

### 4.2 コンパクション（将来的な拡張）
*   ファイル数が増加した場合、全デバイスのデータを統合した「マスター版」を書き出し、古い個別ファイルを削除する仕組みを検討する。

## 5. 制約事項
*   **ファイル数**: デバイス数 × コレクション数のファイルが作成される。
*   **読み込み負荷**: 起動時の Pull 処理において、全マニフェストの取得とパースが必要。
