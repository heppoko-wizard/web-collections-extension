# ADR 002: ブックマーク寄生型同期（Bookmark Parasite Sync）の採用

## ステータス
提案中

## 背景
現在の「ローカルフォルダ同期（File System Access API）」には以下の深刻な課題がある：
1. **権限の消失**: ブラウザ再起動やサイドパネル開閉のたびにフォルダアクセス権限がリセットされ、ユーザーに再許可を求めるポップアップが頻発する（UXの著しい低下）。
2. **バックグラウンド同期の制限**: Service Workerからはユーザー許可なしにファイルシステムにアクセスできず、自動同期が不安定。
3. **設定の複雑さ**: 同期フォルダの選択やデバイス名の管理など、ユーザー側の初期設定コストが高い。

## 提案：ブックマーク同期への寄生
Google Chrome標準の「ブックマーク同期機能」をデータトランスポート層として利用する。

### 1. 基本コンセプト
- **Backend**: Chrome標準ブックマーク（Googleアカウント経由で自動同期）。
- **Cache/UI Storage**: IndexedDB（高速表示、全文検索、画像メタデータ保持）。
- **Synchronizer**: ブックマークイベント（`chrome.bookmarks.onX`）を監視し、IndexedDBと相互に同期する。

### 2. データ構造のマッピング

| 拡張機能の概念 | ブックマークの概念 | 実装詳細 |
| :--- | :--- | :--- |
| 同期ルート | ルートフォルダ | `その他のブックマーク` > `[WC] Web Collections` |
| コレクション | サブフォルダ | ルート直下のフォルダ名 = コレクション名 |
| アイテム | ブックマーク | 各フォルダ内のブックマーク |
| 表示順序 | ブックマークの順序 | `index` プロパティをそのまま利用 |

### 3. メタデータのエンコード
ブックマークの `title` フィールドに、不可視または識別可能な形式でメタデータをシリアライズして埋め込む。

**形式案:**
`[WC]{"id":"UUID","u":1715340000,"m":"メモ内容"}[元のタイトル]`
- `[WC]`: 拡張機能管理対象であることを示すプレフィックス。
- `{"id":...}`: IndexedDBと紐付けるための唯一の識別子、更新日時(`u`)、メモ(`m`)。
- `[元のタイトル]`: ユーザーに見えるタイトル。

### 4. 同期アルゴリズム

#### A. 送信（Push）
サイドパネルでの操作（追加・編集・並び替え）が発生した際、対応するブックマークを即座に操作する。
- **追加**: `chrome.bookmarks.create`
- **移動（DD）**: `chrome.bookmarks.move`
- **更新**: `chrome.bookmarks.update`

#### B. 受信（Pull / 差分検出）
バックグラウンドおよびサイドパネル起動時に以下を実行：
1. `chrome.bookmarks.getTree` で管理フォルダをスキャン。
2. ブックマーク内の `updatedAt (u)` と IndexedDB 内の `updatedAt` を比較。
3. 新しい方を優先して IndexedDB を更新。
4. インデックス順序に従って IndexedDB の `sortOrder` を再計算。

## 5. メリット
- **パーミッションフリー**: `bookmarks` 権限は一度許可すれば永続的。
- **設定不要**: Googleログインさえしていれば、インストール直後からマルチデバイス同期が動作する。
- **高信頼性**: Googleのインフラによる堅牢な同期。

## トレードオフ・制限
- **画像データの欠落**: ブックマークにはURLとタイトルしか保存できないため、Base64化された画像データは同期できない（URL参照のみ継続）。
- **ブックマーク欄への露出**: ユーザーのブックマーク一覧に管理用フォルダが出現する（システム用である旨を明記して対応）。

## 今後の実装方針
1. `bookmarks` 権限の追加。
2. `storage.js` に `bookmarks` との同期フックを実装。
3. `folder-sync.js` および `sync-manager.js` を廃止、またはオプション化。
